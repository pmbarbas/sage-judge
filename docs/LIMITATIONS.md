# Limitations and claim boundary

- The package accepts pre-reviewed source-to-fact mappings. No natural-language interpretation, automatic ontology learning, independently validated semantic fidelity or model inference is provided.
- Synthetic fixtures were authored within the development programme. Test counts describe implementation mechanics, not real-world accuracy, independent labels, reliability estimates or scientific superiority.
- The direct deterministic comparator shares selected mapping IDs and evaluates posture, not independently discovered evidence coverage. Earlier comparisons showed parity; no speed or accuracy advantage is claimed.
- Coverage is relative to the supplied registry, authorised query, finite theory and trusted mapping scope. It does not prove that the real-world source universe is complete. Completeness rules and witnesses must be independently justified outside the library.
- Hashes do not authenticate origin; proof verification only establishes derivations from admitted premises. Shared implementation replay is not independent semantic truth verification.
- Unsupported reachable dependency scope or body-only variables cause refusal. No general relational reasoning, selective-impact assurance, production security or regulatory suitability is claimed.
- Advisory output is inert; execution authority is always NONE. Do not use it as a substitute for an authorised human or application decision.
- CLI path checks are not a race-free filesystem sandbox. Use a private nonconcurrently modified root. Caller must enforce process, network and filesystem isolation where needed.
- Public version 0.1.0 is experimental. Compatibility with private candidate records is not promised. Re-adjudicate trusted inputs and verify with the same implementation version.
